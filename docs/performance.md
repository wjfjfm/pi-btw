# 大会话性能

复跑（隔离临时目录，不读取用户会话，不调用真实模型）：

```bash
npm run build
node --max-old-space-size=8192 bench/large-session.mjs 2000
# 对照其他版本：BTW_BENCH_DIST=/path/to/baseline/dist node ...
```

构造 2000 轮继承历史，再追加 2000 轮 BTW 对话。每轮包含用户正文、thinking、工具调用、约 48 KB 工具结果和助手正文；最终 **235.4 MiB / 16001 条记录**。基线为 `c4b3d31`，以下为本机单次测量，非延迟保证。

| 阶段 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次窗口渲染（160 列） | 13864 ms | 82 ms |
| 连续获取预览 20 次 | 21002 ms | 0.4 ms |
| 合并到空闲 BTW 的投递 RPC | 10098 ms | 1.5 ms |

投递基准使用固定 1500 ms 的模拟模型；旧 RPC 还会等待整个目标回合和历史 IPC，**这不是模型生成或落盘确认变快了**。新 RPC 仅表示已派发，源 BTW 仍需匹配当前目标分支的落盘回执才允许关闭。

## 改动

- 创建/恢复先显示窗口，子进程后台初始化；显示 `starting…`，输入等待初始化后发送，Ctrl+C 可取消尚未发送的输入。
- 首屏只格式化末尾 40 条消息，PageUp 按需加载更早历史；不删除历史、不改变模型上下文。
- 新快照直接用已有 manager 生成预览；运行中的预览由 worker 推送。静态文件预览缓存根据 inode、大小、mtime、ctime 失效，仅缓存短文本。
- 首末正文从两端查找，不再格式化所有中间对话。
- 摘要在后台生成，窗口和 Esc 可用；保留原有 Summary 默认值。生成失败保留源分支。
- 目标投递不等待其回答。回执轮询对未变化的文件不重复解析，但仍验证当前分支，不能仅凭 IPC 成功关闭源。

## 仍存在的耗时

- 本次约 117.7 MiB 的父分支快照复制/写盘约 **1.86 s**，目前仍为同步操作。
- 完整 worker 初始化约 **3.33 s**，其中历史解析约 **1.03 s**；窗口不再等待初始化结束。
- 117.7 MiB 新分支原文序列化约 **626 ms**，Strip 解析/过滤约 **238 ms**。
- Summary Yes 仍需要一次真实模型请求，耗时取决于模型与网络；Summary No + Strip 不请求摘要模型。
- 活跃目标文件变化后，回执检查仍需重新解析；历史 IPC 仍传完整投影。这些是后续可进一步优化的方向。

`ChildSession.startupTimings` 记录 network/resources/history/sdk/footer/extensions/state/total，便于继续定位；total 包括进程与模块启动及 IPC，分阶段计时从 worker 收到 init 后开始。
